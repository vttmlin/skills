# 拷问清单

拷问结束前，每一项都要写出具体内容。「无」也是有效答案，但必须是用户确认过的「无」。

1. **验收标准**：逐条列出，每一条都能写成单测断言或明确的手动验证步骤。
2. **边界情况**：空数据、网络失败、超大数据、重复操作、遥控器和触屏两种输入方式。
3. **Non-goals**：这次明确不做的事。
4. **受影响的已有 requirement**：列出 `openspec/specs/<capability>/spec.md` 里的每一条，并标注「保留 / 修改 / 删除」。
5. **数据与配置**：新增或改动的配置字段、持久化数据，以及老数据如何兼容。
6. **手动验证点**：哪些行为单测覆盖不到（UI、焦点、播放器），以及对应的验证步骤。
7. **术语**：新出现的领域术语已经写进 `GLOSSARY.md`；做出的决定已经写进 `docs/adr/`。
8. **用户确认**：用户明确说了「没有遗漏」。
