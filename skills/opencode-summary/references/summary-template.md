# 总结文件模板

本文件定义总结输出的 frontmatter 格式、内容结构和总结 prompt 规则。

## 输出文件格式

每个总结文件使用以下结构：

```markdown
---
session_id: {main-session-id}
title: {会话标题}
child_sessions:
  - {child-session-id-1}
  - {child-session-id-2}
time_created: {ISO 8601 创建时间}
time_updated: {ISO 8601 更新时间}
generated_at: {ISO 8601 总结生成时间}
---

### 会话目标
[1-2 句话描述这次会话要完成什么]

### 关键决策
- [记录会话中做出的重要技术/业务决策及原因]

### 业务知识发现
- [从对话中发现的项目特性、业务规则、约定俗成]

### 工具使用模式
- [会话中频繁使用的工具/模式]

### 待跟进事项
- [未完成的任务、遗留问题、需要人工确认的点]
```

## 总结 Prompt 规则

对每个会话的内容进行总结时，遵循以下规则：

1. **不包含代码片段或代码变更摘要** — 总结关注知识和决策，不是代码 review
2. **不包含 skill 指令内容** — 过滤掉 `<skill-instruction>` 块
3. **聚焦于「项目知识」而非「操作日志」** — 提取有复用价值的信息
4. **无显著知识时** — 如会话内容无有价值知识，直接输出「无显著知识沉淀」作为整篇内容
5. **语言** — 使用中文总结（匹配用户交互语言）
6. **简洁** — 每个字段控制在 3-5 个要点以内，避免冗长描述
